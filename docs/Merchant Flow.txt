Hypertron Merchant Flow

Purpose
This document describes the target merchant journey after Hypertron evolves from a dashboard + payment links product into a developer-first payments platform with hosted checkout, API keys, and webhooks.

Core Product Promise
A merchant should be able to:
1. Sign up.
2. Create a business profile.
3. Generate API keys.
4. Make one POST /payments request from their backend.
5. Redirect a customer to Hypertron Checkout.
6. Receive a payment.completed webhook.
7. Mark the order as paid without needing to understand Stellar internals.

Merchant Journey

Phase 1: Merchant onboarding
1. Merchant signs up to Hypertron using the current app auth flow.
2. Hypertron creates or resolves the merchant business workspace.
3. Merchant lands inside the dashboard.
4. Merchant completes business setup:
   - business name
   - email
   - logo
   - default settlement currency
   - success URL
   - failure or cancel URL
   - webhook URL
5. Merchant is now ready to integrate.

Phase 2: Developer setup
1. Merchant opens the Developers section.
2. Merchant generates:
   - test public key
   - test secret key
   - live public key
   - live secret key
3. Hypertron shows the quickstart flow:
   - install SDK or use REST
   - create payment
   - receive webhook
4. Merchant copies the test secret key into their backend.

Phase 3: Merchant integration flow
1. Merchant backend calls Hypertron:
   POST /payments
2. Request payload includes:
   - amount
   - currency
   - customer email
   - metadata such as orderId
3. Hypertron authenticates the API key.
4. Hypertron creates a Payment object.
5. Hypertron creates a Checkout Session for that payment.
6. Hypertron returns:
   - payment_id
   - checkout_url
   - status
7. Merchant backend sends the checkout URL to the frontend or redirects the customer.

Phase 4: Customer payment flow
1. Customer opens the Hypertron hosted checkout page.
2. Checkout shows:
   - merchant branding
   - amount
   - asset or currency
   - payment instructions
   - wallet connect or payment action
3. Customer signs and submits the Stellar payment.
4. Hypertron shows live payment state:
   - awaiting payment
   - pending
   - confirmed
   - completed
5. On success, Hypertron redirects to the merchant success URL.
6. On failure or cancel, Hypertron redirects to the merchant failure URL.

Phase 5: Hypertron settlement and reconciliation flow
1. Hypertron detects the on-chain payment through its payment verification and reconciliation layer.
2. Hypertron verifies:
   - destination
   - asset
   - amount
   - memo or attribution data
3. Hypertron updates the payment lifecycle:
   - created
   - pending
   - confirmed
   - completed
4. Hypertron records immutable payment events for auditability.

Phase 6: Merchant webhook flow
1. Once the payment reaches completed, Hypertron creates a payment.completed event.
2. Hypertron signs the webhook payload.
3. Hypertron delivers the webhook to the merchant endpoint.
4. Merchant backend validates the signature.
5. Merchant backend marks the related order or invoice as paid.
6. If delivery fails, Hypertron retries and stores webhook delivery logs.

Phase 7: Merchant dashboard flow
After integration, the merchant uses Hypertron as the control plane for payment operations.

Dashboard sections
- Overview: volume, payment count, pending and completed states
- Payments: payment list, status, amount, customer, transaction hash, timestamps
- API Keys: create, reveal once, rotate, revoke
- Webhooks: endpoint management, delivery logs, retry visibility
- Customers: lightweight customer records derived from payment metadata
- Developers: quickstart docs, code snippets, API reference
- Settings: branding, redirects, webhook defaults, default currency

Net Product Flow
The end-to-end product loop becomes:

Merchant App
-> Hypertron Payments API
-> Hypertron Checkout
-> Stellar Settlement
-> Hypertron Reconciliation
-> Hypertron Webhooks
-> Merchant App

What Changes For Hypertron
Before this build:
- Hypertron is mainly a dashboard + payment links + treasury/privacy rails product.

After this build:
- Hypertron becomes a developer-first merchant payments platform with:
  - merchant control plane
  - API keys
  - hosted checkout
  - payment lifecycle engine
  - webhook delivery system
  - merchant-facing dashboard on top of the same payment data model

MVP Success Condition
The MVP is successful when a new merchant can:
1. Create an account.
2. Generate a test API key.
3. Create a payment from their backend in a few lines of code.
4. Send a customer to Hypertron Checkout.
5. Receive a signed payment.completed webhook.
6. Update their own system without manually checking Stellar.
